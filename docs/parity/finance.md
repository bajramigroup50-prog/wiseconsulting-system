# Finance parity audit (legacy → server)

Area: banka · devizni · bankFmt · blagajna · ppNal · fiskPer · kompenzacii · pocetna · nalozi · kartici · bkAdv · kkart ·
analitika · poobjekti · bilanc · bbPart · recon · recFree · pozajmici · kamati · kursna · konto.

Legacy = `legacy/index.html`, final behaviour (base view + every wrapper, ACT override and change listener). Line numbers
refer to legacy. Status: **ok** = already the same before this pass · **✅** = was missing / different, fixed on this branch
(what was done) · **n/a** = intentionally not ported (reason) · **open** = still missing (reason, see “Remaining”).

Hard rule (coordinator): every list / report / card / book / document screen has PDF, Excel (and CSV) and import wherever
legacy had it or a comparable screen has it. Every screen with `Hd` gets the generic „⬇ PDF“ / „⬇ Excel“ (`ScreenExport`
from main); screens with a dedicated legacy PDF / Excel layout have it as well (rows marked **PDF/Excel/Import**). Shared
building blocks added: `components/parity-fin/export-bar.tsx` (PDF of an area + .xlsx + CSV), `components/parity-fin/table-import.tsx`
(Excel/CSV import + template), `components/parity-fin/confirm-link.tsx`, `lib/parity-fin.ts` (xlsx/CSV route responses),
`Hd` prop `excel={false}` (add-only) for screens with their own legacy Excel.

New table (schema `packages/db/src/schema/parity-finance.ts`, migration to be generated by the coordinator):
`journal_overrides` (manual corrections of document nalozi). New AI kinds (text column, no migration): `ob`, `rec`, `bankcls`.

## Remaining (with reasons)

- banka: KB `.300` files of a special account (offer „Додај сметка 108x“) and KB balance-only files — rare bank-specific
  edge cases; the KB parser does not expose the account / balance-only record yet.
- kartici: bank counterparty name / purpose in the „без комитент“ table and `kcSod` text on the card print — journal lines
  do not carry the statement line id; needs a line-level link in the bank posting.
- fiskPer: per-day goods issue after a multi-day post (the issue plan works per posted record in the manual editor); long receipts are not cut into tiles (whole images are sent).
- The firm-backup / bulk-confirmation „📁 архивирај“ (dossier) is part of the reconciliation-archive work of another agent.
